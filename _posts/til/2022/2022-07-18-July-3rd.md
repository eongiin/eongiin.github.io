## ✏️ 좋은 코드 작성법
### 가독성 높이는 습관

#### null 핸들링
- 선언과 동시에 초기화 (null 발생하지 않도록)
- Assertion 문은 쓰지 말자
- Null은 되도록 직접 핸들링 하지 말자
- JDK 1.8+에서 제공하는 유틸을 적극 활용 (Objects)
- Primitive type, Reference type으로 nullable 여부 나타내기
- List는 null 대신 emptyList()
- null을 대체할 스태틱 객체 리턴 (null object pattern)
- Optional

#### Optional
- Null을 직접 핸들링하지 않음
- Null 여부를 타입만으로 나타낼 수 있음
- 체이닝을 통한 중간 및 종단 처리
- 제대로 사용하기
  - 결과가 없을 땐 null 대신 Optional.empty()
  - 어떠한 일이 있어도 Optional.empty()는 null로 리턴하면 안 됨
  - 중간/종단 메서드로 안전하게 처리 가능
  - 기존 시스템이 null을 리턴하면 Optional.ofNullable로 감싸서 사용
    - 많이 쓰면 오히려 가독성이 떨어질 수 있음 주의
  - Optional은 함수의 반환 타입을 위해 만들어짐 → 필드에 써야 할 땐 한 번 더 고민 필요
  - 컬렉션은 Optional 대신 비어있는 컬렉션 사용

## ✏️ 좋은 코드 작성법
### 가독성 높이는 습관

#### Side effect 줄이기
- 한 번에 다뤄야 할 문제의 크기를 줄이기
  - 나누어서 생각하기 (로직 분해하기)
  - (가능하다면) 순수 함수로 만들기
  - 순수 함수로 만들 수 없다면 사이드 이펙트 모아두기
  - 전역 변수 제거하기
    - 전역변수의 문제점
      - 코드 어디서든 참조하므로, 참조 가능한 모든 지점에서 사이드 이펙트 발생 가능
      - 변수의 LifeCycle 길어짐 (언제 어디서 어떻게 사용하는지 추적하기 어려움)
      - 전역변수가 엮이는 모든 곳에, 보이지 않는 커플링이 발생 (테스트 어려움)
      - 멀티 쓰레드 상황에서 자원 획득을 위한 경합 발생
  - 불필요한 변수 제거하기 (가능하다면 변수 없애기)
  - 불변(immutable) 객체 사용하기

#### 심플하게 구성하기
- 본질에 집중하기 (화려한 것에 속지 않기)
  - 내가 풀어야 하는 문제가 무엇인가?
- 부정문보다 긍정문 사용하기
  - 긍정문을 통해 논리 단순화 시키기 (feat. 캡슐화)
- 논리 깊이 줄이기
  - Early return을 통해 단순화 시키기
  - 분기문의 내용이 길다면, 심플한 것 우선 처리하기
- 비즈니스 로직만 남기기
  - 상세 구현은 숨기고 비즈니스 로직만 표현하기
  
#### 심미적 방법들

#### 주석

  - 하위 호환성이 문제될 경우
  - 서비스 장애 등 사유로 기존과 다른 흐름/룩 등이 추가된 경우

#### 익셉션 핸들링

오류(Error)
  - unchecked
  - OutOfMemoryError, StackOverFlowError, ...

예외 (Exception)
  - checked
  - RunTimeException (unchecked)
    - 예외처리를 강제하지 않음
    - 런타임에 체크됨
    - 종류
      - NullPointerException
      - IllegalArgumentException
      - ArithmeticException
      - IndexOutOfBoundsException
  - Other Exceptions (checked)
    - 호출하는 대상에게 예외처리를 강제함 (명시적인 처리 필요)
    - 컴파일 타임에 체크됨
    - 종류
      - ClassNotFoundException
      - IOException
      - FileNotFoundException
      - SQLException
      - NoSuchMethodException

<b>잘못된 핸들링</b>

- return 값을 통안 에러 핸들링
  - 함수를 호출한 모든 곳이 복잡해짐
  - 유사한 에러 로직 중복
  - 새로 추가된 에러에 대해 빠뜨리기 쉬움

<b>올바른 핸들링</b>

- throw 활용하기
- catch 절에서 잡은 익셉션은 반드시 처리하기
- 익셉션은 정말 예외 상황일 때만 쓰기
- 최상위 Exception 하나로만 잡지 않기
- call stack 잃어버리지 않기
- 너무 많은 CustomException 지양하기
  
- Checked Exception
  - Runtime Exception으로 감싸서 던지기

private Map<String, Object> parseWeather(String jsonString) {

    JSONParser jsonParser = new JSONParser();
    JSONObject jsonObject;

    try {
        jsonObject = (JSONObject) jsonParser.parse(jsonString);
    } catch (ParseException e) {
        throw new RuntimeException(e);
    }
    Map<String, Object> resultMap = new HashMap<>();

    JSONObject mainData = (JSONObject) jsonObject.get("main");
    resultMap.put("temp", mainData.get("temp"));
    JSONArray weatherArray = (JSONArray) jsonObject.get("weather");
    JSONObject weatherData = (JSONObject) weatherArray.get(0);
    resultMap.put("main", weatherData.get("main"));
    resultMap.put("icon", weatherData.get("icon"));
    return resultMap;
}

3) db에 저장하기

diary DB 생성

```sql
CREATE TABLE diary (
    id INT NOT NULL PRIMARY KEY AUTO_INCREMENT,
    weather VARCHAR(50) NOT NULL,
    icon VARCHAR(50) NOT NULL,
    temperature DOUBLE NOT NULL,
    text VARCHAR(500) NOT NULL,
    date DATE NOT NULL
);
```

```java
public void createDiary(LocalDate date, String text) {
    //open weather map에서 날씨 데이터 가져오기
    String weatherData = getWeatherString();

    //받아온 날씨 json 파싱하기
    Map<String, Object> parsedWeather = parseWeather(weatherData);

    //파싱된 데이터 + 일기 값 db에 넣기
    diaryRepository.save(Diary.builder()
            .weather(parsedWeather.get("main").toString())
            .icon(parsedWeather.get("icon").toString())
            .temperature((Double) parsedWeather.get("temp"))
            .text(text)
            .date(date)
            .build());
}
```

## ☃️ Weather Diary Project

### Spring 트랜잭션

#### Transaction

데이터베이스의 상태를 변화시키기 위해 수행하는 작업 단위

- 트랜잭션의 연산
  - 커밋 (Commit)
  - 롤백 (Rollback)

<b>여러 트랜잭션이 경쟁하면 생기는 문제</b>

1. Dirty Read
2. Non-Repeatable Read
3. Phantom Read


#### Spring에서의 트랜잭션

<b>@Transactional</b>

클래스, 메서드 위에 어노테이션을 추가할 수 있다  
트랜잭션 기능이 적용된 프록시 객체 생성  
(Platform Transaction Manager)  

<b>Spring 트랜잭션의 세부 설정들</b>

1. Isolation (격리 수준)
  - 트랜잭션에서 일관성이 없는 데이터를 허용하는 수준
  - DEFAULT   
  - READ_UNCOMMITTED (Dirty Read 발생)
  - READ_COMMITTED (Dirty Read 방지)
  - REPEATABLE_READ (Non-Repeatable Read 방지)
  - SERIALIZABLE (Phantom Read 방지)
  - `@Transaction(isolation=Isolation.DEFAULT)`

2. Propagation (전파 수준)
  - 트랜잭션 동작 도중 다른 트랜잭션을 호출하는 상황
  - 트랜잭션을 시작하거나 기존 트랜잭션에 참여하는 방법에 대해 결정하는 속성값
  - REQUIRED (Default), SUPPORTS, REQUIRES_NEW, NESTED, ...

3. ReadOnly 속성
  - 트랜잭션을 읽기 전용 속성으로 지정
  - `@Transactional(readOnly=true)`

4. 트랜잭션 롤백 예외
  - 예외 발생했을 때 트랜잭션 롤백시킬 경우를 설정
  - `@Transactional(rollbackFor=Exception.class)`
  - `@Transactional(noRollbackFor=Exception.class)`
  - Default : RuntimeException, Error

5. timeout 속성
  - 일정 시간 내에 트랜잭션을 끝내지 못하면 롤백
  - `@Transactional(timeout=10)`

### 날씨 저장 스케줄링

#### 매일 새벽 1시에 날씨 데이터 불러오기

@Scheduled(cron="0 0 1 * * * ")

- second (0-59)
- minute (0-59)
- hour (0-23)
- day of the month (1-31)
- month (1-12) (or JAN-DEC)
- day of the week (0-7) (or MON-SUN -- 0 or 7 is Sunday)

ex)
- 0 0 * * * * : 매  시각
- */10 * * * * * : 10초마다
- 0 0 8-10 * * * : 매일 8시, 9시, 10시


#### Spring Scheduler

- 매일 1시에 API로 날씨 정보를 불러와서 저장해 놓을 테이블 생성

```sql
CREATE TABLE date_weather (
    date DATE NOT NULL PRIMARY KEY,
    weather VARCHAR(50) NOT NULL,
    icon VARCHAR(50) NOT NULL,
    temperature DOUBLE NOT NULL
);
```

- WeatherApplication에 `@EnableScheduling` 달아주기
- DateWeather Entity 생성
- DateWeather Repository 생성
- Diary Service에 매일 새벽 1시에 정보 가져오는 메서드 추가

```java
@Transactional
@Scheduled(cron = "0 0 1 * * *")
public void saveWeatherDate() {
    dateWeatherRepository.save(getWeatherFromApi());
}

private DateWeather getWeatherFromApi() {
    //open weather map에서 날씨 데이터 가져오기
    String weatherData = getWeatherString();

    //받아온 날씨 json 파싱하기
    Map<String, Object> parsedWeather = parseWeather(weatherData);

    return DateWeather.builder()
            .date(LocalDate.now())
            .weather(parsedWeather.get("main").toString())
            .icon(parsedWeather.get("icon").toString())
            .temperature((Double) parsedWeather.get("temp"))
            .build();
}
```

- 앞으로 날씨 정보를 가져올 때는 먼저 date_weather에 해당 날짜에 대한 정보가 있는 지 확인하고 있으면 그 정보를 활용하고, 없으면 현재 날짜를 사용하기로 정함

```java
public void createDiary(LocalDate date, String text) {
    //날씨 데이터 가져오기 (API에서 가져오기 or DB에서 가져오기)
    DateWeather dateWeather = getDateWeather(date);

    diaryRepository.save(Diary.builder()
            .weather(dateWeather.getWeather())
            .icon(dateWeather.getIcon())
            .temperature(dateWeather.getTemperature())
            .date(dateWeather.getDate())
            .text(text)
            .build()
    );
}

private DateWeather getDateWeather(LocalDate date) {
    List<DateWeather> dateWeatherListFromDB =
            dateWeatherRepository.findAllByDate(date);
    if (dateWeatherListFromDB.size() == 0) {
        //정책상 현재 날씨를 가져오도록 함
        return getWeatherFromApi();
    } else {
        return dateWeatherListFromDB.get(0);
    }
}
```
