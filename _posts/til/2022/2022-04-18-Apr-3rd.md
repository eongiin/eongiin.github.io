#### 비교

- 두 배열의 내용이 같은지 확인하고 싶을 때는 `Arrays.equals(a,b)`를 쓴다  
  - 이 방법은 병렬로 위치별로 배열을 반복하고 모든 요소 쌍에 대해 == 연산자를 적용한다  
  - 순서에 상관없이 같은 값들을 가지고 있는지 확인하려면 정렬 후 비교해야 한다
- 이차원 배열을 비교하고 싶을 때는 `Arrays.deepEquals(a,b)`

```java
int[] arr = {1, 2, 3};
int[] arr2 = {1, 2, 3};
System.out.println(arr2 == arr);//false
System.out.println(arr2.equals(arr));//false
System.out.println(Arrays.equals(arr2, arr));//true

int[] arr3 = arr;
System.out.println(arr3 == arr);//true
System.out.println(arr3.equals(arr));//true
System.out.println(Arrays.equals(arr3, arr));//true

int[] arr4 = arr.clone();
System.out.println(arr4 == arr);//false
System.out.println(arr4.equals(arr));//false
System.out.println(Arrays.equals(arr4, arr));//true
```


#### 복사

**1차원 배열**  

- 얕은 복사
  - 단순히 배열의 주솟값만 복사
  - 여러 배열이 같은 주소를 참조하기 때문에 어느 한 배열의 값을 변경하면 같은 주소를 참조하고 있는 배열들은 함께 변경된다
  - `a=b`와 같이 복사하면 얕은 복사가 된다

```java
int[] arr = {1, 2, 3};
int[] arr2 = arr;

arr[0] = 100;
System.out.println(Arrays.toString(arr));//[100, 2, 3]
System.out.println(Arrays.toString(arr2));//[100, 2, 3]
System.out.println(arr == arr2);//true
```

- 깊은 복사
  - 배열의 실제 값을 새로운 배열로 복사
  - `배열명.clone();`
  - `Arrays.copyOf(original, newLength)` : 처음 ~ 원하는 지점까지 깊은 복사
  - `Arrays.copyOfRange(original, from, to)` : 원하는 지점 깊은 복사 
  - `System.arraycopy(src, srcPos, dest, destPos, length)`

```java
int[] arr = {1, 2, 3};
int[] arr2 = arr.clone();
int[] arr3 = Arrays.copyOf(arr, arr.length);
int[] arr4 = Arrays.copyOfRange(arr, 0, arr.length);
int[] arr5 = new int[arr.length];
System.arraycopy(arr, 0, arr5, 0, arr.length);

//false
System.out.println(arr.equals(arr2));
System.out.println(arr.equals(arr3));
System.out.println(arr.equals(arr4));
System.out.println(arr.equals(arr5));

//true
System.out.println(Arrays.equals(arr, arr2));
System.out.println(Arrays.equals(arr, arr3));
System.out.println(Arrays.equals(arr, arr4));
System.out.println(Arrays.equals(arr, arr5));
```
**2차원 배열**  
- 이중 for 문으로 일일이 값 복사

```java
int[][] arr = { {1, 2, 3}, {4, 5, 6, 7} };
int[][] arr2 = new int[arr.length][];

for (int i = 0; i < arr.length; i++) {
    arr2[i] = new int[arr[i].length];
    for (int j = 0; j < arr[i].length; j++) {
        arr2[i][j] = arr[i][j];
    }
}

System.out.println(Arrays.deepEquals(arr,arr2));//true
System.out.println(Arrays.equals(arr,arr2));//false
```

- `System.arraycopy(src, srcPos, dest, destPos, length)` 이용

```java
int[][] arr = { {1, 2, 3}, {4, 5, 6, 7} };
int[][] arr2 = new int[arr.length][];

for (int i = 0; i < arr.length; i++) {
    arr2[i] = new int[arr[i].length];
    System.arraycopy(arr[i], 0, arr2[i], 0, arr[i].length);
}

System.out.println(Arrays.deepEquals(arr,arr2));//true
System.out.println(Arrays.equals(arr,arr2));//false
```

#### 정렬

- 오름차순 : `Arrays.sort(배열명)`
- 내림차순 : `Araays.sort(배열명, Collections.reverseOrder())` 
- int 배열을 내림차순 정렬 하고 싶을 때는 Integer 배열로 바꿔줘야 한다

```java
int[] arrInt = {3, 1, 4, 9, 5, 3};
String[] arrString = {"paasdf", "abddd", "ca", "dda", "fa", "Ca"};
Arrays.sort(arrInt);
Arrays.sort(arrString);
System.out.println(Arrays.toString(arrInt));//[1, 3, 3, 4, 5, 9]
System.out.println(Arrays.toString(arrString));//[Ca, abddd, ca, dda, fa, paasdf]

Integer[] arrInteger = Arrays.stream(arrInt).boxed().toArray(Integer[]::new);
Arrays.sort(arrInteger, Collections.reverseOrder());
Arrays.sort(arrString, Collections.reverseOrder());
System.out.println(Arrays.toString(arrInteger));//[9, 5, 4, 3, 3, 1]
System.out.println(Arrays.toString(arrString));//[paasdf, fa, dda, ca, abddd, Ca]
```

- 정렬하고 싶은 범위를 지정할 수도 있다
  - `Arrays.sort(arrInt,fromIdx,toIdx);`
  - toIdx는 포함 안 됨

## ✏️ OOP 개념 (Java)

- OOP 4가지 특징
  - 추상화(Abstraction) : 어떤 영역에서 필요로 하는 속성이나 행동을 추출하는 작업
  - 캡슐화(Encapsulation) : 객체와 객체 간의 의사소통을 위한 정보만 노출하고 내부 동작은 숨김
    - 높은 응집도와 낮은 결합도를 유지할 수 있도록 설계해야 요구사항을 변경할 때 유연하게 대처할 수 있다
  - 상속(Inheritance) (일반화) : 공통된 부분은 상속받기
    - 일반화 관계는 자식 클래스를 외부로부터 은닉하는 캡슐화의 일종
    - [참고](https://gmlwjd9405.github.io/2018/07/05/oop-features.html){:target="_blank"}
  - 다형성(Polymorphism) : 외부에 보이는 모습은 한 가지 형태지만 실질적으로 쓰이는 기능은 여러 가지 역할 수행
    - ex) 오버 로딩, 오버라이딩


- 클래스 멤버 변수는 자동으로 초기화된다
- 지역변수는 꼭 초기화해 줘야 한다

  ```java
  Student s1 = new Student();
  //클래스의 멤버변수는 자동으로 초기화
  System.out.println(s1.getName());//null
  System.out.println(s1.getNumber());//0
  String name;
  //        System.out.println(name);에러 -> 지역변수는 초기화 꼭 해줘야 함
  ```

- 기본 생성자는 자동으로 추가되지만 사용자 정의 생성자를 만들면(오버 로딩) 기본 생성자는 자동으로 추가되지 않는다
  - 이때 기본 생성자를 사용하고 싶으면 직접 추가해 주면 된다
  - `public 클래스명(){}`
- 오버 로딩할 때는 파라미터의 개수나 타입이 달라야 한다(반환 타입만 다른 것은 x)

  ```java
  public Student(int number) {
      this.number = number;
  }

  //이미 int형 변수 하나를 받는 생성자가 있음
  //public Student(int age){
  //    this.age=age;
  //}
  ```

- this 생성자는 생성자 안에서 한 번만 호출 가능

  ```java
  public Student(String name, int number) {
      this(name);
  //        this(number); 한 번만 가능
      this.number = number;

  }
  ```
- 생성자가 무조건 public은 아니다
  - ex) Calendar 클래스
    - 생성자들이 protected로 선언되어 있다
    - 즉, 이 클래스를 확장해서 구현하지 않으면 생성자로 객체를 만들 수 없다
    - getInstance() 사용

- 멤버 변수 정의할 때 객체별로 달라지는 값이 아니고 공통된 값이면 static 이용
  - 객체를 생성하지 않아도 접근 가능
- 값이 바뀌지 않으면 final -> 한 번 초기화 후 값 변경 못함  
(final + 메소드는  자식에서 오버라이딩 하지 못함)
- 보통 멤버 변수로 final을 설정하면 static을 함께 써서 정적으로 하는 것이 좋다
- 멤버 변수 초기화 방법
  - 명시적 초기화 `private int amount=30;`
  - 초기화 블럭

  ```java
  }
  ```

    - 인스턴스 초기화 블럭

```java
public class Student {
    private String name;
    private int number;
    private int age;
    public static String schoolName;
    private int grade;

    //클래스 초기화 블럭
    static {
        schoolName = "zb";
    }

    //인스턴스 초기화 블럭
    {
        grade = 1;
    }

    //생성자
    public Student() {
    }

    public Student(String name) {
        this.name = name;
    }

    public Student(int number) {
        this.number = number;
    }

    //이미 int형 변수 하나를 받는 생성자가 있음
    /*public Student(int age){
        this.age=age;
      }*/
    public Student(String name, int number) {
        this(name);
        //this(number); 한 번만 가능
        this.number = number;

    }

    public Student(String name, int number, int age) {
        this(name, number);
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public int getNumber() {
        return number;
    }

    public int getGrade() {
        return grade;
    }

    @Override
    public String toString() {
        return "Student{" +
                "name='" + name + '\'' +
                ", number=" + number +
                ", age=" + age +
                ", grade=" + grade +
                '}';
    }
}
```

### 사용자 모드와 커널 모드

**필요성**  
사용자가 만든 응용 프로그램이 컴퓨터를 망가뜨릴 수 있다  
사용자 프로그램이 하드웨어 구성요소와 직접 상호작용하거나 임의의 메모리 공간에 접근하는 것을 방지하기 위해 두 가지 모드로 나눴다

**커널 모드**  
- 시스템 모드
- 하드웨어에 액세스 가능

**사용자 모드**  
- CPU와 메모리에 대한 액세스가 제한 됨

하드웨어 리소스에 액세스하려면 프로그램이 OS에 요청해야 한다  
커널은 그 요청을 검토하고 승인하면 사용자 프로그램을 대신하여 하드웨어 구성요소와 상호작용한다

**CPU Protection Ring**  
- 커널 모드와 사용자 모드를 구현하는 일반적인 방법
- CPU에 무엇인가 실행할때마다 protection ring에 적혀있는 level 정보를 확인하여 level값이 중요한 영역을 처리하기에 적합하면 처리하고 그렇지 않으면 실행하지 않는다

### 프로세스

- 실행 중인 프로그램

**프로세스 스케쥴링**

- 배치 처리 시스템 (FIFO)
- 시분할 시스템 : 다중 사용자 지원, 컴퓨터 응답시간 최소화
- 멀티 태스킹 : 단일 CPU에서 여러 응용프로그램을 동시에 실행하는 것처럼
- 멀티 프로그래밍 : CPU를 일정 시간당 최대한 많이 활용
- 멀티 프로세싱 : 여러 CPU에서 하나의 응용 프로그램을 병렬로 실행해서 실행 속도 ↑
- SJF (Shortest Job First)
- Priority-Based (정적, 동적)
- Round Robin

## 💻 Operating System

<b>프로세스 구조</b>

- code 
- data 
- stack
- heap

<br>
<b>Process Control Block (PCB)</b>

- 운영체제가 프로세스를 제어하기 위해 정보를 저장해 놓는 곳
- 프로세스의 상태 정보를 저장하는 구조체

<br>
<b>Context Switching</b>

- CPU에 실행할 프로세스를 교체하는 기술
- PCB에 있는 PC(Program Counter), SP(Stack Pointer) 이용
- 실행 중지할 프로세스 정보를 PCB에 업데이트하고 메인 메모리에 저장
- 메인메모리에 있는 다음 실행할 프로세스 정보를 CPU의 레지스터에 넣고 실행

<br>
<b>InterProcess Communication (IPC)</b>

- 프로세스간 통신 방법 제공
- 대부분 커널 공간 공유하는 방식
  - Message Queue
  - Shared Memory
  - Pipe
